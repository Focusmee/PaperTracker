# PINFINDER Python 模拟实验

> [!goal] 实操完成标准
> 在运行程序之前预测四个合成场景的结果；运行后能从报告回到原始事件，并用自己的话解释三条规则。命令成功不等于学习完成。

代码位置：`D:\Projects\研讨厅\pinfinder_demo`

## 安全边界

- 只读取项目内的合成 JSON，不访问真实 App、设备或网络。
- 不安装 Soot、Frida、Burp，不处理 JAR/AAR 或 APK。
- 输出是教学规则的结果，不是对真实软件的漏洞或法律结论。
- 程序使用确定性规则，不调用在线大语言模型。

## 人与 Agent 的分工

| 环节 | Agent 可以做 | 人必须理解和决定 |
|---|---|---|
| 读数据 | 解释 JSON 字段、整理时间线 | 每条事件代表什么证据 |
| 预测 | 提示遗漏的条件 | 在运行前亲自写下 PASS/VIOLATION/UNKNOWN |
| 运行 | 执行命令、排查路径错误 | 知道程序读取了哪个案例 |
| 核对 | 指出报告引用的事件 | 判断证据是否支持中文解释 |
| 修改 | 帮助编辑合成事件 | 预测修改会影响哪条规则 |
| 结论 | 总结候选问题 | 不把合成报告称为真实漏洞或违法事实 |

## 步骤一：先读 API 模型并预测

- **目的：** 先理解规则依据，避免把程序输出当答案背诵。
- **为什么需要：** 同一事件只有结合参数含义、调用顺序和行为承诺才能判断。
- **输入：** `pinfinder_demo/privacy_api.json` 与 `pinfinder_demo/cases/*.json`。
- **人的动作：** 找出用户选择、设置调用、初始化和数据访问四类事件，在纸上预测三条规则。
- **Agent 的动作：** 只解释字段，不提前透露案例答案；按要求提示缺失证据。
- **预期输出：** 一张手写预测表，每个规则填写 PASS、VIOLATION 或 UNKNOWN 及理由。
- **验证与掌握标准：** 能指出预测依赖的具体事件，而不是只说“看起来有问题”。

## 步骤二：运行一个场景

- **目的：** 观察规则分析器怎样把事件变成可回溯报告。
- **为什么需要：** 实操重点是连接“规则—证据—结论”，不是记命令。
- **输入：** 一个案例名。
- **人的动作：** 明确自己即将运行哪个案例，并保留步骤一的预测。
- **Agent 的动作：** 可以代为运行命令和解释报错，但不能代替人的预测。
- **预期输出：** 三条规则各一个状态、中文原因和证据事件编号。
- **验证与掌握标准：** 能在案例 JSON 中逐条找到报告引用的证据。

在项目根目录运行：

```powershell
.\.venv\Scripts\python.exe -m pinfinder_demo.analyze --case compliant
```

查看全部案例：

```powershell
.\.venv\Scripts\python.exe -m pinfinder_demo.analyze --all
```

## 步骤三：核对而不是接受答案

- **目的：** 训练人工复核，而不是训练复制 Agent 结论。
- **为什么需要：** 真实研究中，文档抽取、参数语义和事件归因都可能错误。
- **输入：** 控制台报告、API 模型、对应案例 JSON。
- **人的动作：** 对每条报告回答“依据在哪、缺什么证据、能否有其他解释”。
- **Agent 的动作：** 帮助定位引用位置、解释代码分支、提出反例。
- **预期输出：** 对三条规则各写一句自己的解释和一句边界说明。
- **验证与掌握标准：** 即使隐藏程序状态，也能根据证据重新得到同一判断。

## 步骤四：修改一条事件再预测

- **目的：** 证明自己理解因果关系，而不是记住固定案例。
- **为什么需要：** 能预测变化才说明掌握了规则。
- **输入：** 任意案例副本。
- **人的动作：** 只修改一个值或删除一条事件，先写下哪条规则会改变。
- **Agent 的动作：** 帮助创建副本并运行，不替人预测。
- **预期输出：** 修改前后报告差异。
- **验证与掌握标准：** 能解释为什么只有某一条或某几条规则发生变化。

建议修改：

1. 把用户选择从 `false` 改成 `true`。
2. 把设置调用移到初始化之后。
3. 删除数据观察窗口结束事件，观察为什么结果变成 UNKNOWN。

## 最少记忆清单

1. 规则输出必须引用原始事件。
2. UNKNOWN 表示缺证据，不等于安全或违规。
3. Agent 可以运行和解释，但人负责证据含义与结论边界。

## 主动回忆题

1. 为什么 `setConsent(false)` 出现了，Behavior 仍可能是 UNKNOWN？
2. 用户拒绝但下游设置缺失时，哪条规则最直接？
3. 如何区分“没有发生数据访问”和“没有足够时间观察”？
