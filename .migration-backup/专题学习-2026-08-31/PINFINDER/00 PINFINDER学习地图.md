# PINFINDER 零基础学习地图

> [!goal] 最终目标
> 不依赖 Android、安全分析工具或论文原文，能够用一个 `App → Wrapper → AdSDK` 例子解释：PINFINDER 收集哪些证据、三条规则分别检查什么、为什么最后仍需要人工复核。

## 进入条件

- 会阅读简单 Python、JSON 和 `if` 判断。
- 不要求了解 Android、APK、逆向、Soot、Frida 或 Burp。
- 每次只学习 20–30 分钟；没有通过检查点就不进入下一单元。

## 唯一贯穿案例

一个儿童向的游戏 App 通过广告中介 Wrapper 接入 AdSDK。用户选择“拒绝个性化广告”，App 需要把选择正确传给下游 SDK；SDK 也必须兑现“不再访问模拟广告标识符”的承诺。

```text
用户选择
  ↓
Host App（宿主应用）
  ↓
Wrapper（中介组件）
  ↓
AdSDK（广告功能组件）
  ↓
模拟数据访问
```

## 暂时不要做

- 不安装或使用 Soot、Frida、Burp、Root 设备。
- 不分析真实 APK，不对真实 App 作风险结论。
- 不背 16 类 PIN、全部统计数字或所有工具参数。
- 不让 Agent 替你决定证据是否足够。

## 复习路线

第一次：按六个单元顺序完成。第二次：只复述贯穿案例和三条规则。第三次：更改 Python 场景，预测输出后再运行。

## 最少记忆清单

1. 文档说明“应该怎样”，运行事件说明“实际怎样”。
2. PINFINDER 把分散证据按时间组织后，检查使用、遗漏和行为兑现。
3. Agent 能辅助提取和分析，但结论必须回到文档、代码或事件证据。

## 主动回忆题

1. 为什么只抓到网络请求，还不能告诉开发者究竟漏调了哪个 SDK 设置？
2. 为什么静态代码里存在一个隐私方法，不代表运行时已经调用？
3. 为什么调用了“拒绝”方法，也不能直接证明 SDK 停止访问数据？

## 学习完成标准

- [ ] 能用白话解释 SDK、Wrapper、隐私 API 和 PCTrace。
- [ ] 能对给定轨迹分别提出正确使用、触发和行为检查问题。
- [ ] 能运行 Python 模拟器，并指出报告对应的原始事件。
- [ ] 能说明模拟器是教学模型，不是法律或真实 App 检测器。
