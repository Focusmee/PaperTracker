# 8 相关工作
先前的研究 [12]、[13]、[14]、[15]、[16]、[17]、[18] 广泛研究了与 CMP 管理的网站 cookie 横幅相关的隐私风险。这些研究强调了一系列合规性问题，包括在用户做出任何选择之前存储同意（即默认同意）、缺乏退出选项以及使用预先选择的选择来引导用户同意[12]、[13]、[15]。研究人员还发现，网站往往无法尊重用户的偏好，即使在用户选择退出后仍继续收集和共享个人数据[12]、[13]、[14]、[16]。为了检测和分析此类违规行为，已经开发了多种工具。例如，研究[14]、[17]建议使用客户端工具来识别同意字符串生成和传输中的问题。 CookieBlock [18] 进一步通过应用机器学习对 cookie 进行分类并直接在浏览器中强制用户同意，显示超过 94% 的网站至少存在一种类型的 GDPR 违规行为。虽然这些技术在 Web 环境中有效，但在很大程度上依赖于特定于浏览器的功能，例如 JavaScript 检测、HTTP cookie 标头和客户端同意字符串 - 集成到移动应用中的 CMP中通常不具备这些功能。相反，移动应用通常依赖于本地存储、专有 SDK 接口或后端 CMP API，使得现有的基于 Web 的 CMP 分析技术难以直接应用。在移动平台上，多项研究表明，应用开发者实施的同意对话框可能会带来类似的风险[7]、[8]、[9]、[10]，包括缺乏有意义的退出选项和不遵守用户选择。
然而，这些研究主要关注内部实施，而不是 CMP，后者由于更广泛的采用而变得越来越重要。例如，2023 年进行的一项研究 [8] 发现，排名前 100 的应用中只有 6.6% 采用了 CMP。相比之下，我们使用 2024 年底收集的应用（比 [8] 晚一年左右）进行的研究表明，排名靠前的应用中 CMP的采用率显着增加（Android 上为 7.2%，iOS 上为 4.5%），这可能是受到监管压力和处理个人数据的第三方SDK的广泛使用推动的。这一趋势强调了对移动应用中 CMP的设计和使用进行系统调查的必要性。为了解决这一差距，我们引入了用于 CMP界面 分析的新工具，并提出了有关其合规行为的新颖的实证研究结果。
