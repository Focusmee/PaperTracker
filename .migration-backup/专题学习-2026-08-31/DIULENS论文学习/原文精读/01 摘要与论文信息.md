# 摘要
当今的移动应用 (app) 越来越多地重用第三方SDK 来提供基本功能。然而，将这些 SDK集成到应用的供应链中会带来复杂性，使得管理 SDK 并确保其集体遵守隐私法规变得具有挑战性。最近，同意管理平台（CMP）出现，越来越多地被移动应用采用作为集中机制和应用全局配置来帮助管理 SDK，特别是使应用中的所有 SDK 能够在个人数据处理方面遵守相同的用户同意状态。然而，采用既定的 CMP 是否可以确保用户同意的有效性（特别是在移动应用中）的问题仍有待探讨。本研究通过对现实世界移动应用（跨 Android 和 iOS）中使用 CMP界面 获取用户同意相关问题进行首次系统调查，解决了这一知识空白。为了实现这一目标，我们开发了一个新颖的框架 DIULENS，它使用一系列专为 CMP 定制的大语言模型辅助 GUI 分析技术来高效、全面地发现 CMP界面。该框架分析 CMP界面 和应用内的实际 SDK使用情况，以识别 CMP的隐私可问责设计、实施和使用的违规行为（CMP DIU风险或简称 DIU风险）。我们的研究结果揭示了各种 DIU风险，例如未能正确且一致地披露第三方SDK、用户与 CMP界面 交互导致的模糊同意效果，以及难以撤回或强制同意的情况。归因于原因，我们发现应用开发者对 CMP的使用（或配置）和有缺陷的 CMP实现或其组合都可能导致 DIU风险。
我们进一步观察到 Android 和 iOS 平台上 CMP的采用和 DIU风险存在差异，这可能受到特定于平台的隐私功能的影响，例如 Apple 的应用跟踪透明度 (ATT) 框架。这项研究提供了新的见解，并弥合了关于确保 CMP 在移动应用中获得有效用户同意的关键知识差距。 *两位作者对这项工作做出了同等贡献。
