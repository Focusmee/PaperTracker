# 3 CMP隐私可问责设计、实现与使用规则
CMP 有助于获取和管理用户对应用使用的 SDK 处理个人数据的同意。同意有效且符合隐私要求
![[附件/论文截图/DIULENS/image-02.png]]
图2：Usercentrics CMP的第一层与第二层界面。第一层提供概览和主要选择，第二层展示供应商、目的与细粒度设置。
通过结合 CMP的标准，我们提出了四项规则（概述如下）来指导、定义和规范现实应用中 CMP的隐私可问责设计、实施和使用。这些被称为 CMP 设计、实现和使用规则，统称为 DIU规则。
### DIU规则1：CMP界面的出现时机
CMP界面 应该让用户指定是否同意（或拒绝）单个 SDK进行数据收集或收集目的。规则 1 与 CMP界面 应在应用中显示的时间有关。根据主要隐私法规[5]、[35]、[39]的要求，在收集个人数据之前必须获得用户同意。在 CMP的上下文中，应在任何 SDK 开始收集个人数据之前显示请求同意的应用的 CMP界面。
### DIU规则2：CMP界面披露信息的可信性
应用中的 CMP界面 必须可靠地披露有关所使用的各个 SDK的信息，使用户能够为 SDK的数据收集和目的提供知情同意 [40]。规则 2 要求 CMP界面 上 SDK的披露信息准确无误。根据我们对 CMP指南 [21]、[35] 的分析，披露的信息通常包括第三方SDK的数量、SDK列表、其法律依据状态、处理数据的目的以及收集和处理的数据的类别。为确保准确性，所披露的信息必须与应用的实际 SDK集成实践保持一致。例如，CMP界面 上披露的 SDK数量必须与集成到应用中的实际数量匹配。
### DIU规则3：可撤回且不受强迫的用户同意
隐私法规，例如 GDPR 第 7(3) [27] 条，规定用户有权随时撤回同意。在 CMP的背景下，应用应确保在用户最初同意（或拒绝）后 CMP界面 仍可访问，从而允许用户轻松撤回或修改其对 SDK的同意状态（可撤回用户同意）。此外，用户对 CMP界面 的同意必须由用户自由给出[35]。例如，如果应用的功能并非绝对必要，则应允许用户拒绝任何 SDK的数据收集或收集的特定目的（非强制用户同意）。
### DIU规则4：用户与CMP界面交互所产生的同意效果应明确无歧义
知情同意的一个关键前提是用户通过 CMP界面 的导航始终会产生清晰、明确的同意效果。此要求可适用于每个用户与 CMP界面 的交互或 CMP 内的导航路径。例如，当用户单击按钮或更改复选框的状态时，应清楚地显示最终的同意状态。此外，用户通过多个 CMP界面 的导航应该提供一致的体验，没有任何模糊的用户体验。上述 DIU规则是根据我们对有效同意要求的理解而制定的（考虑 GDPR 等隐私法规）。它们并不意味着完整，而是旨在涵盖 CMP界面 应满足的最低要求。请注意，我们专注于捕获影响所获得的用户同意的有效性并在最终用户与 CMP界面 交互中体现的规则，而不强调其他方面，例如不直接与最终用户交互的同意信号的后端处理。
