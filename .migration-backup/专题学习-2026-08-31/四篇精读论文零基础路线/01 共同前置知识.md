# 共同前置知识


## 单元一：一款 App 背后不只有一个开发者

### 三个新术语

- **Host App（宿主 App）**：用户安装的主体应用。例：儿童游戏本身。
- **SDK（软件开发工具包）**：被集成进 App 的现成代码。例：广告 SDK 获取设备信息、请求广告。
- **Wrapper（封装/中介 SDK）**：包在一个或多个底层 SDK 外面，替 App 统一调用它们。例：广告聚合 Wrapper 根据价格选择广告平台。

```text
用户 → 儿童游戏（宿主） → 广告聚合 Wrapper → 广告 SDK A/B → 广告服务器
```

关键点：Wrapper 可能由第三方供应商提供，不必然是宿主开发者亲手编写；但 App 开发者选择集成它，因此仍需理解并正确配置责任链。


## 单元二：三种证据不要混在一起

### 三个新术语

- **Static Analysis（静态分析）**：不运行程序，检查安装包、字节码、调用和数据关系。例：发现代码里存在读取 OAID 后调用网络函数的路径。
- **Dynamic Analysis（动态分析）**：运行程序并记录真实操作和事件。例：点击“拒绝”后观察本次运行是否调用广告接口。
- **Ground Truth（基准真值）**：由可靠标注或人工核验得到、用于判断工具对错的参考答案。例：两名研究者复核同一条泄露路径。

| 证据 | 能说明 | 不能单独说明 |
|---|---|---|
| 静态路径 | 某行为在代码结构上可能发生 | 本次运行一定发生 |
| 动态日志 | 某行为在这次环境与路径中发生 | 其他路径绝不会发生 |
| LLM 判断 | 界面或文本更可能表达什么 | 漏洞已经被事实证实 |


## 单元三：程序分析就是追踪“值从哪来到哪去”

### 三个新术语

- **Source（源）**：敏感数据进入分析范围的位置。例：`getOAID()` 返回广告标识符。
- **Sink（汇）**：数据离开或产生风险的位置。例：`http.post()` 把内容发到网络。
- **Taint Analysis（污点分析）**：给 Source 的值贴上“敏感”标签，沿赋值、参数和返回值传播，检查是否到达 Sink。

```java
id = getOAID();       // Source：id 被标为敏感
payload = wrap(id);   // 标签继续传播
http.post(payload);   // Sink：形成候选路径
```

这不是断言“数据一定泄露”，而是生成一条需要核验的候选证据链。



## 单元四：智能体不是只问一次大模型

### 三个新术语

- **Agent Loop（智能体循环）**：观察当前状态、选择动作、执行、再验证状态的反复过程。
- **Visual Grounding（视觉定位）**：把“点击隐私设置”落到屏幕上的具体坐标或控件。
- **Replay（重放）**：把成功动作保存为确定性脚本，之后无需再次让模型猜测。

```text
截图/UI树 → 判断下一步 → 点击 → 检查页面是否改变 → 记录 → 下一轮
```

LLM 适合把“拒绝个性化广告”映射到界面语义；Appium/ADB 适合真正执行点击；监督模块适合检查动作有没有成功。
