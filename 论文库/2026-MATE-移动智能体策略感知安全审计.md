# MATE：基于合成轨迹学习的移动智能体策略感知安全审计

> [!abstract] 一句话结论
> MATE 把移动智能体的任务指令、执行轨迹和可编辑自然语言安全策略一起输入轻量模型，输出是否违规、风险类别和理由；它用 158 个 App 的知识合成超过 14 万条训练轨迹，并以人工核验和真实设备轨迹评估降低纯 LLM Judge 或固定规则的局限。

## 为什么与当前研究相关

### 来源事实

MATE 面向能在真实手机上跨 App 执行多步操作的智能体，审计对象不是某一帧截图，而是完整操作轨迹是否违反 App 或用户策略。官方页面、项目页和代码仓库均已访问；正式 PDF 的正文页码与作者在论文中陈述的完整局限尚待进一步精读核实。

### 我的理解

它适合接在 DIULENS Demo 的 Appium/Agent 之后：Appium 负责产生可验证操作记录，MATE 类审计器负责比较“这条路径做了什么”和“策略允许做什么”。这提供了比“把所有截图直接问通用 LLM”更清楚的分工。

### 与 DIULENS / PICOSCAN 的关系

- 与 [[论文库/2026-DIULENS-移动CMP隐私风险]]：两者都消费操作路径和事件上下文。DIULENS 的目标是检查 CMP 与同意时序；MATE 的目标是对任意移动智能体轨迹执行策略条件化审计。
- 与 PICOSCAN：PICOSCAN 以 SDK/API 与调用关系检查集成责任；MATE 不分析 APK 调用图，而是分析运行后形成的 ReAct 风格轨迹。二者证据层级不同，不能互相替代。
- 可迁移点：把 DIULENS 四条规则写成可编辑策略文本，同时保留原本确定性规则计算结果，用于比较“规则引擎”和“策略模型”的一致性与误差。

## 研究问题、输入与输出

- 问题：怎样在不为每次策略变化重新训练的情况下，低延迟审计异构移动智能体的长轨迹？
- 输入：用户任务指令、包含 Thought/Action/Observation 的轨迹，以及一条或多条自然语言安全策略。
- 输出：是否违规、风险类别和自然语言理由。
- 研究对象：合成轨迹、未见 App 的合成轨迹，以及 AutoGLM、Mobile-Agent 等在真实设备上形成的轨迹。
- 威胁边界：MATE 是事中/事后的轨迹审计器，不是 Android APK 漏洞扫描器，也不能仅凭输出证明某个 App 本身存在漏洞。

## 系统完整工作链路与分工

```text
158个中英文App
  ↓ 收集功能描述、操作工作流、安全策略
App知识库
  ↓ 指令合成 → 轨迹合成 → 标注合成 → 质量检查与修复
14万+策略条件化训练轨迹
  ↓ 数据增强 + 监督微调
MATE 0.5B / 1.5B / 3B
  ↓ 部署时：原始Agent日志 → 轨迹适配器 → 策略检索器
指令 + ReAct轨迹 + 相关策略
  ↓
违规判断 + 风险类别 + 理由
```

| 部分 | 具体职责 | 证据边界 |
|---|---|---|
| 静态分析 | 原系统不反编译 APK，也不构建调用图 | 不能证明 SDK/API 的静态调用关系或潜在未执行路径 |
| 动态数据 | 轨迹适配器把真实 Agent 日志统一成步骤序列；真实集包含设备运行噪声 | 审计看到的是被记录的动作与观察，漏记事件会造成证据缺口 |
| LLM / 模型 | 合成指令、轨迹与标注；训练后的轻量模型执行策略条件化分类和解释 | 模型解释不是 Ground Truth，仍需策略标签和人工结果对照 |
| 知识库 | 保存 158 个 App 的功能描述、工作流和安全策略，为轨迹合成与策略检索提供依据 | 不是单纯 SDK 名单；知识过期或覆盖不足会影响新 App 泛化 |
| 人工验证 | 质量流水线最终由人工审计合成样本；真实轨迹子集也由人工采集和标注 | 人工标签仍可能有主观差异，完整标注协议待正式 PDF 精读 |

## 零基础术语与例子

- **移动智能体（Mobile Agent）**：能理解任务并操作手机的模型系统。例如用户说“把优惠券发给朋友”，Agent 自动打开聊天 App、选择联系人并发送。
- **执行轨迹（Trajectory）**：任务期间按顺序记录的思考、动作和界面反馈。例如“点击链接 → 浏览器打开 → 出现恶意页提示”。
- **安全策略（Security Policy）**：允许或禁止行为的文字规则。例如“未经再次确认，不得把链接群发给多个联系人”。
- **策略条件化审计**：同一个动作在不同规则下可能结论不同。例如公司手机禁止打开未知 APK，个人测试机策略可能允许。
- **ReAct 格式**：把推理与动作交替记录为 Thought、Action、Observation，便于审计模型读取完整过程。
- **轨迹适配器**：把不同 Agent 的原始截图、点击日志和回复转成统一结构；类似把多种日志翻译成同一种 JSON。

## 已核验的数据集、基线、指标与关键数字

- 知识来源覆盖 158 个中英文 App，训练语料超过 140,000 条策略条件化轨迹，风险分类为 14 类。
- MATEBench-In：134 个训练域内 App、2,775 条合成轨迹。
- MATEBench-Out：24 个未见 App、1,150 条合成轨迹。
- MATEBench-Real：13 个 App、3 个 Agent、162 条真实设备轨迹。
- 对照包括固定规则引擎、通用 LLM Judge、ShieldAgent、ShieldLM，以及外部 R-Judge、ASSEBench 测试集。
- MATE-3B 在 In/Out/Real 上准确率分别为 96.83%、95.48%、95.06%；Real 的 F1 为 95.60%。
- 单张 H100 上，MATE-0.5B 审计一条 Out 轨迹约 0.09 秒，MATE-3B 约 0.21 秒。
- 项目页的受控消融中，0.5B 模型在 Real 上同时去掉外部知识和质量修复时准确率为 46.91%，两者均保留时为 75.93%；这组数字来自特定消融设置，不能与最佳 3B 的 95.06%直接比较。

> [!warning] 正确解读
> 95.06% 是 162 条 MATEBench-Real 轨迹上的准确率，不是任意 App、任意策略或真实漏洞的普遍检出率。模型判断仍应保留输入轨迹、策略文本和人工标签以便复核。

## 局限与复现条件

### 来源可确认的复现条件

- 代码库提供数据合成、模型部署、策略检索、轨迹适配和评估目录，以及 `run_minimal_demo.sh`。
- 完整运行需要 MATE 模型权重、三个 MATEBench 子集和本地策略检索模型；评估理由相似度还依赖 `BAAI/bge-large-zh-v1.5`。
- 代码仓库示例使用 Linux shell，并给出只构造小子集、不启动模型服务的快速检查方式。

### 我的理解与待正文核实

- 自然语言策略可能含糊、冲突或检索错误，模型准确率不能解决策略本身定义不清的问题。
- 合成轨迹和真实轨迹的动作分布接近，不等于语义风险分布完全相同。
- App 功能、UI 和策略会更新，知识库需要版本与更新时间，否则可能把旧规则用于新行为。
- 审计发生在日志可见层；操作系统调用、SDK内部数据流和未记录网络事件仍需其他静态/动态工具提供证据。
- 正式论文的完整伦理说明、标注一致性和失败案例仍待 PDF 精读。

## 思考题

1. 为什么同一条 Agent 轨迹在不同自然语言策略下可能得到相反结论？
2. MATE 的“动态”体现在哪里，为什么它仍不是动态污点分析？
3. 若轨迹只保存点击坐标和截图，哪些隐私事件可能完全不可见？
4. 知识库、策略检索器和审计模型分别可能引入什么错误？
5. 如何把 DIULENS 四条规则改写成策略文本，同时保留可计算规则作为 Ground Truth？
6. 162 条真实轨迹的 95.06% 能否推出真实商店全部 App 上也有同样准确率？为什么？
